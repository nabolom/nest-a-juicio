# Caso único — ¿cómo lanzar Cobranza Pro?

Horizonte, una empresa ficticia de software de facturación, planea lanzar **Cobranza Pro** el 15 de octubre. El equipo debe decidir si lanza, lanza como piloto cerrado o pospone.

## Las cuatro perspectivas

| Área | Hecho disponible | Tensión que introduce |
|---|---|---|
| Producto | La funcionalidad principal está lista. Para cambiar el flujo de consentimiento se requieren diez días hábiles de congelamiento y prueba. | El 15 de octubre no deja margen para cambiar el flujo antes de un lanzamiento amplio. |
| Ventas | Hay 40 clientes interesados; 12 pertenecen a sectores regulados. El compromiso comercial promete acceso el 15 de octubre. | Ventas quiere cumplir la fecha y evitar perder el pipeline. |
| Riesgo | Los clientes de sectores regulados requieren inscripción manual hasta que se apruebe el modelo de consentimiento. | Riesgo no autoriza activación automática para esos 12 clientes. |
| Operaciones | Dos personas pueden completar como máximo 15 inscripciones manuales durante la primera semana. | Un piloto controlado es viable; una activación amplia puede rebasar la capacidad. |

## Tu trabajo

Propón una decisión de lanzamiento y un plan de 72 horas. La respuesta debe tener exactamente estas secciones:

```text
DECISIÓN: LANZAR / PILOTO CERRADO / POSPONER

EVIDENCIA POR ÁREA
- Producto: …
- Ventas: …
- Riesgo: …
- Operaciones: …

TENSIONES QUE DEBEMOS RESOLVER
1. …
2. …

PLAN DE 72 HORAS
1. [dueño] — [acción] — [condición de terminado]
2. [dueño] — [acción] — [condición de terminado]
3. [dueño] — [acción] — [condición de terminado]

LO QUE NO PODEMOS AFIRMAR TODAVÍA
- …
```

## Restricciones

- No afirmes que el consentimiento está aprobado: no lo está.
- No propongas activar automáticamente a los 12 clientes regulados.
- El plan no puede depender de más de 15 inscripciones manuales durante la primera semana.
- No inventes fechas, aprobaciones ni recursos.
